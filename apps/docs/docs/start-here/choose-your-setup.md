# Choose Your Setup

ContextGo 可以承接很多能力，但不是所有人都应该从同一种配置开始。

选 setup 的目标不是“身份标签”，而是避免你一上来启用太多层能力。

## 怎么选

选 setup 时，只看三个问题：

1. 你主要在哪个设备上执行真正工作
2. 你是否需要频繁离开桌面继续任务
3. 你当前更接近“自己用”，还是“对外服务”

## Setup 1：Desktop-Only

适合：

- 主要在一台电脑前工作
- 第一阶段只想把本地闭环跑顺
- 暂时不依赖远程接入和渠道发布

建议先准备：

- 一台稳定桌面主机
- 一个 ready runtime
- 一个最常用工作台
- 基础上下文材料

这通常是最稳、最适合第一阶段的 setup。

## Setup 2：Desktop + Web

适合：

- 偶尔需要离开桌面
- 仍然以电脑为主，只是想在浏览器里继续查看和控制任务
- 需要轻量远程访问，但不一定依赖手机壳层

建议先准备：

- 已稳定的桌面主机
- 浏览器可访问的远程入口
- 适合继续查看、总结、跟进的任务类型

## Setup 3：Desktop + Mobile

适合：

- 不想一直守在电脑前
- 希望在手机上继续看状态、继续一小步、上传材料
- 任务仍然由桌面主机执行

建议先准备：

- 持续在线的桌面主机
- 已验证可用的远程接入
- 手机端主要承担查看、控制和上传

不建议把它理解成“手机替代桌面”。

## Setup 4：Builder Setup

适合：

- 独立开发者
- 经常使用代码型 runtime
- 项目文档、浏览器研究和本地工具对结果质量影响很大

建议先准备：

- 一个代码工作最常用的 runtime
- 项目说明和项目文档
- 浏览器上下文
- 最少量但高价值的 commands / hooks

## Setup 5：Publication Setup

适合：

- 目标是把 Agent 发布到真实渠道
- 本地闭环已经初步成立
- 当前需要考虑 audience、渠道和权限边界

建议先准备：

- 一个本地已跑顺的 Agent 或工作流
- 一个明确目标渠道
- 一个清晰 audience
- 一条保守的首发路径

如果本地能力还没稳定，不建议直接进入这个 setup。

## 选不准时怎么办

如果你不确定选哪个，默认推荐顺序是：

1. 先从 **Desktop-Only** 开始
2. 真有远程需要，再扩到 **Desktop + Web** 或 **Desktop + Mobile**
3. 真有对外目标，再进入 **Publication Setup**
