# Product Map

如果你把 ContextGo 只理解成一个聊天页，会错过它真正的结构。

更准确的理解方式是把它看成 7 条相互配合的产品主轴：

## 1. Workbench

这是你真正开始工作的地方。

它不是单一聊天页，而是一个可以承接不同工作类型的工作台宿主。

## 2. Context

这是 ContextGo 最核心的长期价值层。

它负责把文件、网页、浏览器上下文、项目文档和外部来源接进来，并持续演化成长期可复用上下文。

## 3. Agents & Capabilities

这一层回答：

- 你有哪些 Agent
- 用哪个 runtime 执行
- 如何通过 packages、skills、hooks、commands、schedules 给系统装能力

## 4. Publish

这一层让一个本地跑顺的 Agent 能够进入真实渠道，变成面向 audience 的服务入口。

## 5. Collaboration

这一层让系统从单 Agent 工作走向多 Agent、group 和 harness 风格工作流。

## 6. Remote & Devices

这一层定义桌面主机、网页端、手机端和 Linux Host 的关系。

## 7. Manage

这一层承接账号、设备、设置、权限和故障排查。
