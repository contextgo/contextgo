# Desktop Host

在 ContextGo 的多端模型里，桌面主机不是某个可有可无的入口，它是执行权威。

## 它负责什么

桌面主机默认负责：

- 文件与工作目录
- runtimes
- tools
- 长任务
- 本地环境相关能力
- 任何依赖主机权限的动作

## 为什么必须理解这一点

因为这会直接影响：

- 为什么手机不能完全替代桌面
- 为什么主机在线状态如此重要
- 为什么“远程使用”和“本地执行”是两件事
- 为什么一些动作必须依赖主机权限而不是客户端权限

## 主机在线意味着什么

当你从网页或手机远程接入时，主机在线不只是“设备亮着”。

更重要的是：

- 这台设备仍然持有你的运行环境
- 它还能访问相关文件和工具
- 它可以继续处理当前任务

如果主机离线、退出或环境损坏，远程客户端不会神奇变成新的执行宿主。

## 哪类能力应当留在主机

下面这些能力默认应该保留在主机侧：

- 本地代码工作
- 依赖本地 CLI 或 SDK 的任务
- 大文件处理
- 长时间运行的工作流
- 需要本机权限的连接器或系统能力

## 用户操作上的含义

这意味着更稳的使用方式通常是：

1. 在主机侧启动真实任务
2. 让主机保持稳定和在线
3. 再从网页或手机接入查看和继续

而不是反过来从客户端开始要求系统承载全部执行职责。

## 常见误解

- “我在手机里看到了页面，所以手机就是主机”
- “远程入口打开了，所以本地环境就不重要了”
- “客户端能发起动作，就说明它也在本地执行”

这些理解都不准确。
