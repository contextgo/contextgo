# Use Cases

这一部分不是功能总览，而是按真实工作方式告诉你：ContextGo 应该从哪种模式进入。

## 这页解决什么问题

很多人已经理解了产品模型，但仍然会卡在一个问题上：

> 我到底应该用哪种方式开始，而不是把每个页面都看一遍？

Use Cases 就是为这个问题服务的。

## 怎么选入口

可以先按下面三个维度判断：

- **你的核心工作是什么**
  是编码、研究、写作、运营、发布，还是远程继续任务。
- **你现在最缺的是哪一层**
  是更稳的本地闭环、更顺的远程接入，还是更清晰的对外服务路径。
- **你当前是自己用，还是已经准备对外服务**
  这会直接决定你应该停留在本地工作流，还是继续进入 Publish。

## 推荐起步路径

先按这个顺序：

1. [Bring Your Workflow Into ContextGo](/use-cases/bring-your-workflow-into-contextgo)
2. 再选一个最贴近主工作的页面
3. 用顺以后再回来看 [Recommended Starter Modes](/use-cases/recommended-starter-modes)

优先看：

- [Coding And Builder Workflow](/use-cases/coding-and-builder-workflow)

优先看：

### 如果你准备对外服务

优先看：

## 一个实用原则

一次只选一个主场景，不要同时把自己代入很多 use case。

因为第一阶段最重要的，不是“每个模式都懂一点”，而是：

- 有一个场景真的跑顺
- 你知道这个场景为什么适合自己
- 后续扩展时不会打乱已有闭环
