# Use Cases

This section is not a feature catalog. It shows how ContextGo should be opened through real work modes.

## What this page solves

Many users understand the product model but still get stuck on one question:

> Which entry path should I actually start from?

Use Cases exists to answer that.

## How to choose an entry point

Use three filters:

- what kind of work matters most right now
- which missing layer hurts most: local loop, remote continuity, or external publication
- whether you are still using ContextGo privately or already moving toward external service

## Recommended starting paths

### If you are still learning the product through real work

Start with:

1. [Bring Your Workflow Into ContextGo](/use-cases/bring-your-workflow-into-contextgo)
2. then choose the page closest to your real work
3. come back later to [Recommended Starter Modes](/use-cases/recommended-starter-modes)

### If you are a developer or builder

Start with:

- [Coding And Builder Workflow](/use-cases/coding-and-builder-workflow)
- [Research And Browser Workflow](/use-cases/research-and-browser-workflow)

### If remote continuity matters most

Start with:

- [Personal Remote Workbench](/use-cases/personal-remote-workbench)
- [Remote & Devices](/remote)

### If you are preparing an external service path

Start with:

- [Publish-To-Channel Workflow](/use-cases/publish-to-channel-workflow)
- [Publish](/publish)

## One practical rule

Pick one primary scenario first.

Do not try to identify with many use cases at once in the first stage.  
The first goal is to make one scenario truly work.
