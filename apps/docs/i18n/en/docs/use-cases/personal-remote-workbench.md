# Personal Remote Workbench

ContextGo does not turn your phone into a second host. It lets the desktop host keep working while web and mobile remain available as remote surfaces for checking, controlling, and continuing work.

## Good fit if...

- you do not want to stay in front of the desktop all day
- you want tasks to keep moving while you step away
- you want continuity across browser and phone

## How this differs from ordinary remote control

Many remote tools mostly mirror the desktop screen.

ContextGo is different because it keeps:

- the desktop host as execution authority
- web and mobile as product-level remote entry points
- files, context, and task state inside one system

## What to prepare first

Before using this mode, confirm:

- the desktop host is stable
- at least one runtime is ready
- a real task is already running on the host
- the browser can open the same host successfully

## What the first remote workflow should look like

Recommended order:

1. start the real task on the desktop host
2. open the same host in a browser
3. then connect from the phone
4. begin with status checking, one small continuation step, and one file upload

## What remote surfaces are best for

- checking task progress
- receiving results and continuing the next step
- uploading one local file back to the host
- making a quick follow-up decision

## What still belongs on the host

- large file operations
- runtime-heavy work
- multi-window work
- local development and local automation flows

## Common misunderstanding

Do not interpret this mode as:

- the phone becoming the replacement host
- the web client becoming a long-running execution environment
- remote access removing the need for host-side authority
