# Choose Your Setup

Not every user should start from the same setup.

The goal is not to pick an identity label. It is to avoid enabling too many layers too early.

## How to choose

Use three questions:

1. where does your real execution happen today
2. how often do you need to continue work away from the desktop
3. are you still in private local use, or already moving toward external service

## Desktop-only

Best when:

- you mainly work on one machine
- you want the local loop to work first
- remote access and publication are not first-stage priorities

Prepare:

- one stable desktop host
- one ready runtime
- one primary workbench
- basic context material

## Desktop plus web

Best when:

- you occasionally step away from the desktop
- browser continuity matters
- you want lightweight remote access before mobile shells matter

Prepare:

- one stable host
- one working browser entry path
- tasks that benefit from follow-up and review

## Desktop plus mobile

Best when:

- you do not want to stay in front of the desktop all day
- you want to check progress, continue small steps, and upload material from the phone
- execution still belongs to the host

Prepare:

- one stable always-available host
- one verified remote entry path
- remote-safe task types

## Builder setup

Best when:

- you are a developer or builder
- code runtimes are central to your work
- project docs, browser research, and local tools all affect output quality

Prepare:

- one code-oriented runtime
- project docs and project files
- browser context
- only the highest-value commands or hooks first

## Publication setup

Best when:

- your goal is to serve a real external audience
- one local workflow already works reliably
- you are ready to think about channels, audience, and permission boundaries

Prepare:

- one local workflow that already works
- one target channel
- one explicit audience
- one conservative first release path

## If you are unsure

Default recommendation:

1. start with **Desktop-only**
2. expand to **Desktop plus web** or **Desktop plus mobile** only when needed
3. move into **Publication setup** only after a local loop is already stable
