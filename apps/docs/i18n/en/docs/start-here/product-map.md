# Product Map

If you think of ContextGo as just one chat page, you miss the actual structure.

It is better understood as a set of coordinated product surfaces.

## 1. Workbench

This is where work actually starts.

It hosts:

- conversation and cowork flows
- file, page, and result continuation
- direct interaction with runtimes, context, and tasks

## 2. Context

This is the long-term value layer.

It answers:

- where material comes from
- how it is organized into reusable context
- how later work keeps using earlier results

## 3. Agents & Capabilities

This layer explains how the system gains capability:

- which runtime executes work
- which packages and assistants exist
- how skills, hooks, commands, and schedules extend the system

## 4. Remote & Devices

This layer defines the relationship between:

- the real host machine
- the web client
- the mobile shells
- Linux host modes

## 5. Publish

This layer moves a working local capability into a real external channel.

It is about:

- where users enter from
- which audience is served
- how one capability gets reused across multiple entry points

## 6. Collaboration

This layer extends the system beyond one user and one agent:

- multi-agent collaboration
- group workflows
- harness-style flows

## 7. Manage

This layer keeps the product operable over time:

- account and devices
- settings and updates
- security and permissions
- troubleshooting
