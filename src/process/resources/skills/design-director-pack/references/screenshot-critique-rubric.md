# Screenshot Critique Rubric

Use this rubric when the user gives screenshots, mockups, or screen recordings and wants a design readout.

## 1. First-scan read

Identify in under five seconds:

- what this screen is for
- what the primary action appears to be
- what area attracts attention first

If that read is wrong or slow, call it out.

## 2. Hierarchy and scanning

Check:

- whether the headline, key metric, or primary task actually wins attention
- whether supporting information is visually subordinate
- whether the eye path is clear instead of scattered

## 3. Surface and density logic

Check:

- whether cards, panels, tables, and backgrounds use a consistent surface hierarchy
- whether density matches the screen's job
- whether spacing rhythm helps chunk content

## 4. Action ranking

Check:

- whether the primary action is obvious
- whether secondary actions are correctly demoted
- whether destructive or low-frequency actions are too loud

## 5. Component consistency

Check:

- whether buttons, inputs, tabs, tables, and badges feel like one system
- whether radius, borders, shadows, and text weights drift from component to component

## 6. State quality

Check:

- empty states
- loading states
- error states
- selection and focus visibility

## 7. Preserve before replacing

Always name:

- what already works
- what should remain stable after redesign

## 8. Output priority

Return:

1. the screen read
2. the top issues by severity
3. the system causes
4. the smallest high-value fixes
5. what to preserve
