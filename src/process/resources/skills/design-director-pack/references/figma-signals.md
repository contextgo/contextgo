# Figma Signals

Use these signals when the user references Figma or wants a creative-tool aesthetic with strong system discipline.

This is a first-party distillation from the reviewed `figma/DESIGN.md` sample. It is not a license to copy Figma verbatim.

## Signals worth absorbing

### 1. Monochrome chrome, expressive content

- keep structural UI mostly black, white, and tightly controlled neutrals
- let color live in hero content, canvases, previews, or spotlight zones
- do not spread bright color across every control surface

### 2. Micro-hierarchy through typography

- hierarchy can come from small weight and tracking changes, not only large size jumps
- body copy can stay relatively light if contrast and spacing remain strong
- mono labels can create technical structure without making the whole surface feel mechanical

### 3. Purposeful geometry

- pills and circles feel deliberate when used as a system rather than decoration
- rounded geometry should be consistent across tabs, buttons, chips, and quick actions
- dense work surfaces still need geometric restraint, not bubble overload

### 4. Product-language echoes

- focus rings, selection treatment, or motion cues can echo the product's core interaction model
- this works when it reinforces product identity, not when it becomes gimmickry

### 5. Gallery pacing

- monochrome framing plus colorful showcase zones can make a product feel both precise and creative
- let expressive zones breathe instead of filling every section with visual excitement

## Boundaries to keep

- do not copy Figma's exact token values, wordmark conventions, or page structure
- do not force colorful hero energy into dense operator surfaces
- do not make all typography tight and light if readability drops
- do not use pill geometry everywhere if the existing design system is sharper and more enterprise-oriented

## How to map it into ContextGo work

When absorbing a Figma reference, decide:

1. which signals are structural
2. which signals are surface styling
3. which signals should stay out because they would break the product's existing trust model

Typical outputs:

- a `vibrant-tooling` direction with monochrome control surfaces
- a hybrid system where product chrome stays restrained and expressive content gets the energy
- a component adaptation brief for tabs, icon buttons, hero zones, and spotlight cards
