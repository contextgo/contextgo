# Receiving Code Review

Feedback is input to evaluate, not a script to follow blindly.

Workflow:

1. Read the full feedback before touching code.
2. Restate unclear items or ask for clarification before implementing anything ambiguous.
3. Verify each comment against the actual code, tests, and product constraints.
4. Implement confirmed fixes one item at a time, with validation after each risky change.
5. Push back calmly when feedback is incorrect, out of scope, or conflicts with explicit product decisions.

Do not perform social agreement. Perform technical evaluation.
