# Brainstorming

Design before implementation.

Workflow:

1. Inspect the relevant repository context before inventing structure.
2. Clarify the goal, constraints, and success criteria. Ask only the minimum needed to remove ambiguity.
3. Offer a small set of approaches with trade-offs and a recommendation.
4. Present the design in product and engineering terms: scope, architecture, failure modes, validation.
5. Do not start broad implementation until the design is explicit and the user agrees with the direction.
6. When the design is accepted, hand off to `writing-plans`.

For straightforward tasks, the design can be compact. The rule is not "be verbose"; the rule is "make the approach explicit before coding."
